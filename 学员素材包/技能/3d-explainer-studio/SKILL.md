# 3D 干货科普工作台（学员版）

目标：学员给**口播文案（或选题）**，用**自己的 IP** 做出竖屏 1080×1920 的 3D 角色干货/科普视频：角色在干净的摄影棚里一路做动作、演示要点，画面上有钩子标题、数字卡、进度条、关键词字幕，节奏紧、信息清楚。本风格不卖货；要做带货请改用 `3d-story-daihuo-studio`。

## 素材包位置
本技能依赖《学员素材包》文件夹（里面有 脚本/、音效库/、背景/、规范/、风格/）。找它（记为 PACK）按这个顺序：①环境变量 PACK；②本机固定位置 `~/学员素材包`（Windows 是 `%USERPROFILE%\学员素材包`，安装脚本和下面的「装成自己的技能」会放在这里）；③学员拖进对话的文件夹或 学员素材包.zip（zip 先解压）。三处都没有，就让学员再拖一次。下文的路径都相对 PACK。

## 装成学员自己的技能（第一次开工时先问，只做一次）
学员不想每次都重新拖文件夹或去 GitHub 下载，就把技能和素材包装到本机：
1. 先问学员「要不要把这套技能装到你自己的 Claude 里，以后直接用？」，同意再做，不同意就跳过，别的流程照常。
2. 能运行命令的环境：把 PACK 复制到 `~/学员素材包`（已经在那里就跳过），再把 PACK/技能/ 下的每个技能文件夹（含 `h3-prompt-writing`、`h3-quanneng-cankao-zhongtu-chuxian`）复制到 `~/.claude/skills/`（Windows 是 `%USERPROFILE%\.claude\skills\`），已存在的会被更新。装完告诉学员重启 Claude。素材包里有 install.sh / install.ps1 时直接运行它们也一样。
3. 不能运行命令的环境（比如只在网页或普通对话里）：告诉学员到 Claude 设置里的技能页，把 PACK/技能/ 里的几个 zip（本风格的技能 + 两个 H3 技能）逐个上传；素材包文件夹放在一个固定位置，下次拖进对话即可。
4. 装好后告诉学员以后怎么开工：直接说「用 3d-explainer-studio 技能做一条带货视频」，素材包不用再拖。

## 和其他技能的关系（先读）
- 同一个素材包里还有 `ip-daihuo-video-studio`（阿炎，横屏带货）和 `3d-story-daihuo-studio`（3D 剧情带货）。三个技能**共用** PACK 里的脚本、音效库、背景和渲染模板；各自的画面风格、字幕、转场规则写在各自的技能里。
- **规则冲突时：本技能的规则 > `规范/` 里的通用规范。** 详见 `规范/规则优先级与协调.md`。
- 学员想做带货（有产品、要卖货）：告诉他用 `3d-story-daihuo-studio`，本技能不处理产品带货。
- 剪辑用 `风格/3D剧情带货/渲染模板/`（两个 3D 风格共用，里面已经带了干货需要的元素）。风格细则见 `风格/3D干货科普/风格说明.md`。

## 工作方式
1. 严格按步骤顺序，不跳步，不自己改流程。
2. 每完成一步，用一两句话说：做完了什么、文件放哪、学员下一步要做什么。
3. 需要学员选择时用选择题（没有选择题工具就列 A/B/C 让学员回字母），一次问完。
4. 标【停】的地方必须等学员确认。
5. 不读取、不打印、不复制任何密钥，只确认「存在、能调用」。
6. 学员的文案一字不改（发音修正和断句除外）。

## 第 0 步：开工检查【停】
一次问完：

### 0.1 素材
- 口播文案或选题（只有选题就先帮学员写文案，学员确认后再往下走）。
- 参考视频：可选。有就用「参考帧法」借鉴它的构图和节奏；没有就按文案和风格说明设计。
- 字幕语言：只中文，还是**中英双语**（默认问一次；双语时英文由你翻译，学员确认）。
- 强调色：默认橙红 (255,90,40)，学员可换（一条片子固定一个）。

### 0.2 IP 形象（必须有）
- 学员已有 IP：让他提供角色设定图或母图（最好是干净背景的 3D 质感）。其他画风就按他的画风做，并在提示词里锁定。
- 没有 IP：带他设计。问：性别年龄、体型、发型发色、标志性特征（服装、配饰）、是否有五官（无五官的光滑雕塑质感最容易保持一致）。写出「IP 外貌规格」（体型、服装颜色、材质、禁止项），让学员用出图工具先出一张**母图**，确认后全片只用它。
- 一条视频从头到尾只用一个固定 IP、一套固定服饰（头带、手套、护腕、鞋这类配饰动作镜头里也要保留），不切换、不混用。
- 做系列时，同一个选题想出不同版本，靠服饰、颜色、机位、结尾特效、配音语气区分，不照抄上一版的动作。

### 0.3 配音 API（必须当面确认）
默认用火山语音合成（声音复刻）。逐项问：有没有 AppID、Access Token、自己克隆的声音的 Speaker ID？是否已设置环境变量 VOLC_APPID、VOLC_TOKEN、VOLC_SPEAKER_ID？
- 密钥在学员自己的电脑上。让学员运行 `python3 PACK/脚本/check_env.py --only-tts --test-tts`，把输出（只有 [OK]/[缺失]）贴回。
- 声音必须是学员本人的或已获授权，提醒一次。
- 没配好：先做分镜、出图、H3 提示词，配音和剪辑放后面。

### 0.4 剪辑环境和音效转场（你来跑，必做）
1. 运行 `python3 PACK/脚本/check_env.py`，整理成就绪清单：Python 3、ffmpeg/ffprobe、numpy/Pillow/scipy、中文粗体字体（Noto Sans CJK SC Black，或设 FONT_PATH）。缺什么告诉学员怎么装。
2. 运行 `python3 PACK/风格/3D剧情带货/渲染模板/selftest.py`。它会先检查 `PACK/音效库` 是否完整（缺哪个文件会直接列出来），再用假素材把干货和带货两种示例都渲染、混音一遍。**必须看到「自检通过」才往下做**；音效库不完整就让学员重新下载素材包、别跳过，也不要用代码合成音效顶替。
3. 转场（硬切、放大冲击、推近模糊、甩镜、白闪、黑场亮起）和音效（真实音效）都在素材包里，学员装好素材包就都有，不需要另外安装任何东西。

## 第 1 步：分镜【停】
先读 `风格/3D干货科普/风格说明.md`。

1. **拆镜头表**：镜号、对应旁白、动作、机位、结尾状态。**转场和音效在分镜阶段由你一起想好**（写进镜头表：进场转场、有没有数字卡/关键词/进度条），出图工具只负责出「能帮助剪辑」的分镜图（动作起点清楚、结尾状态明确）。
2. 有参考视频时用**参考帧法**：用 ffmpeg 按镜头截关键帧，先拼联系表看清全片结构，再逐镜截最有力的一帧。**你自己拆好**，把图给出图工具，不让出图工具看视频。每镜给出图工具：参考帧 + 母图 + 一句话改动（「保持参考帧的构图、动作、发光位置，把人物换成这个角色；不要照抄参考帧里的人物脸型、衣服标志、文字、品牌」）。参考视频自带的字幕、数字、logo 一律不画。
3. **动作先为文案服务**：每句话对应最贴切的动作，可以优化超出参考。背景保持干净（默认纯黑摄影棚、黑色湿亮地面）。
4. **镜头长度随文案变化**，不要都固定 5 秒，最长约 10 秒也可以，画面要频繁变化；每个镜头承载更多内容（连续的多个动作、表情变化、运镜、特效放在同一个镜头里），不要靠大量硬切。H3 约 5 秒的片段长度不是限制镜头设计的理由，要靠优化提示词和镜头时长解决。
5. **角色要有情绪**：3D 质感上叠加轻漫画元素（小星星、汗滴、图标气泡），不要重漫画风；加小的肢体语言；神态随旁白变化。
6. 整片场景有变化但连贯，不要重复同款场景；同一版相邻镜机位不重复。
7. **不加文案里没有的内容**（比如错误动作示范）。要求优化分镜时整体重新设计，不是只补几个镜头。

### 分镜图会被当作视频首帧
- 只画**动作起点姿势**，头和身体完整入画，不要只截局部极近景（视频模型会自己补全身体、把镜头拉远）；「特写感」靠发光和细节，不靠裁切；局部特写也用中近景，身体占画面高度约 85%。
- 不要起点/终点帧配对，不要拼贴、不要分屏，**不要残影**（残影会被画成多出一条腿）。需要变化的镜头，由视频完成过程。
- 踩地的动作必须是**平地**，不要台阶（台阶会让视频里脚底错位穿模，高抬腿尤其如此）。

### 选题骨架示例（HIIT，13 镜）
S01 起点状态（正面全身）+ S01B 终点状态（同站姿同机位，只有体脂这一个差别）｜S02 跑步机｜S03 挑战指镜头｜S04 俯卧撑｜S05 深蹲｜S06 登山跑｜S07 开合跳｜S08 高抬腿｜S09 平板支撑｜S10 核心锁死（上半身中近景）｜S11 清空重启｜S12 肌群彩色图｜S13 金色收尾定格。易错动作：平板必须是前臂平板（肘在肩正下方）；开合跳手脚同步；高抬腿是快速弹跳小跑不是慢走。这只是示例，学员的选题按自己的文案设计。

### 自审（出图前必做）
列出镜头表，逐镜检查：动作对应旁白、机位不重复、场景连贯、没有文案之外的内容、转场和音效已想好。通过后给学员确认。

## 第 2 步：出图、审图
1. **一轮一份总单**：每个版本一份 md，每镜同时写「首帧画面」和「视频动作」。返修在同一份里追加一节，不要单独发一堆返修单；大改才升版本号，重出的图用 `文件名_v版本b` 不覆盖。任务单只写要求（如「透明底」），不教出图工具怎么做，也不让它反复核对细节。
2. **出图两步**：先出 2 张定风格，学员确认后，剩下的一次出完。
3. 分镜图提示词代码块顺序：引用母图 / 参考帧 / 场景 / 构图 / 动作与发光 / 发光颜色 / 画幅（竖版 9:16，1080×1920）/ 禁止（文字字幕数字 logo、改变体型材质服饰、多人）。动作用具体姿势词，易画错的写「不是什么」；一镜一个视觉重点；重出写明基于哪一版。
4. 所有提示词写进 md，规则写在文档里。给出图工具的文档末尾附一条可直接复制的「发给出图工具」的消息，一个任务只给一条。
5. **审图检查表（从严，一次审完，只返修有问题的张）**：角色和母图一致、体型没变；服饰和本版一致、没挡住要展示的部位；无 logo 无文字；竖版 9:16，头和身体完整入画；只有一个人，没有残影或多余的腿；动作画对；发光只在目标部位；首帧构图适合做视频；相邻镜机位不重复；场景逐镜连贯。
6. 画面里的文字、数字、字幕一律后期加（用渲染模板），图里不画字；小标签贴着发光部位，不要大字挡住人物。

## 第 3 步：H3 视频提示词【停】
- 严格按 `h3-prompt-writing` 技能（没装就读 PACK/技能/h3-prompt-writing/SKILL.md）的结构写：首帧图和角色母图一起传的镜头用全参考结构，只有首帧的镜头用首帧结构；提示词里不写图片路径，学员自己上传。产品或道具在镜头中途才出现时，再按 `h3-quanneng-cankao-zhongtu-chuxian` 技能写。
- **每条必写五个锁定**：①人物（同一个角色，不变形，不长出多余五官，服饰不变）②亮度（不变暗、不渐黑）③发光（颜色位置保持首帧，±10% 呼吸，不新增特效）④镜头（固定或极缓慢推近≤5%，不跳切、不拉远）⑤动作（只做写明的，易错动作写「不是什么」）；再加「不要残影重影，全身只有两条腿两只手」。视频不生成人声：全片没有对白、旁白和人声，写明角色不说话。
- 已踩过的动作坑：点亮/变身镜头要「同一瞬间」全身亮起；起床镜头首帧就躺着、直接猛然坐起；俯卧撑身体一条直线不塌腰；开合跳双臂完全伸直不弯肘、手脚同步、做满；高抬腿每半秒一拍、膝到腰高、不转身、手不抬到头旁、平地；前臂平板镜头完全固定、不掉膝；喘气镜头只做喘气站直、亮度不变；「清空重启」暗→亮，最后一帧必须比第一帧亮；人物占画面很小的定格镜头动作越简单越好。
- 每镜一个代码块，旁边用中文写镜号、对应旁白、要传的参考图顺序。H3 出片由学员自己完成（常见是约 5 秒的竖版片段），片段放回项目文件夹。
- **视频审片**：同一个角色、没长多余五官、没变暗、没被拉远或切镜、动作和节奏正确、发光保持首帧。问题先判断根源：首帧构图问题→改分镜图；提示词缺锁定→改提示词。某个镜头生成得不好，常用做法是从同版本历史片段里选最合适的替代，不要拼接、乒乓、慢放硬撑。

### 收片与缺镜检查
学员丢视频进来，按画面认镜头（文件名可能乱序，不要按顺序猜），命名 `S01.mp4…`，存进 `clips/`；缺的镜头告诉学员，缺的先用分镜图静图慢推占位。

## 第 4 步：配音【停】
- 文稿里数字按口播写（30秒→三十秒）；一句一个 mp3（01 到 N）；先把文稿给学员看，确认后再生成。角色不开口，一律旁白。
- 参考 `PACK/脚本/配音示例_volc_tts.py` 生成；密钥只来自环境变量，不读取、不打印、不写进文件或命令行。
- **分工：你写配音文稿和一个双击就能跑的脚本，学员自己运行生成**，你再从他的文件夹读 mp3。不要自己去生成配音，也不要跳过这一步。
- 整体语速默认 1.05 倍（可调），停顿压缩。
- **每次生成都不一样**：某句读错或多字，只重生成那一句，其余保留。
- **收到配音先查句尾截断**：每句结束前 30 毫秒的 RMS（归一化后）> 0.04 就是截断，正常在 0.01 以下。截断的句子单独补录，15 毫秒交叉淡化拼回，并重算后面所有句子的时间；杂音或句间多出一小段能量，用 10 毫秒 RMS 包络定位，裁掉并加 30 毫秒淡出。
- 发音问题用「发音修正」解决；**字幕仍写原文**。
- 处理后的逐句配音放 `vo/01.wav…`，另写 `vo/dur.txt`（每行「序号 秒数」）。响度 -14 LUFS。

## 第 5 步：剪辑
先读 `风格/3D干货科普/风格说明.md` 里的剪辑规则，再用 `风格/3D剧情带货/渲染模板/` 出片（先读那里的 README.md，参考示例 `project.example.fitness.json`）：

1. 项目文件夹里放好 `clips/`（H3 片段，S01.mp4…）、`vo/`（处理后的逐句配音和 dur.txt）、`bgm/`（可选）。
2. 复制 `project.example.fitness.json` 为 `project.json`，按本条片子改：`lines`（旁白原文）、`lines_en`（要中英双语才写）、`style`（强调色、字幕里要染色的重点词）、`progress`（有「第几组/第几轮」才写）、`transition_scale`（干货默认 1.8，转场约 0.35–0.4 秒）、`shots`（每镜对应哪句、进场转场、`title` 钩子标题、`step` 进度、`numcard` 数字卡、`keywords` 关键词弹出）。
3. 运行 `python3 渲染模板/render.py 项目文件夹 --dur vo/dur.txt` 渲染画面（想先看效果可加 `--quick S05,S06`）；再运行 `python3 渲染模板/mix.py 项目文件夹 成片_v1.mp4` 混音并合成。
4. 钩子标题只用一个，放第一镜；数字卡、关键词只给真正的重点，不要每镜都有。

不要自己另写渲染脚本；模板满足不了的效果，先告诉学员，再在模板基础上小改。

**硬规则：**
1. **时间轴以配音为准**，每镜按句长截取，不拉伸视频。
2. **转场和音效成对设计**：转场放慢（`transition_scale` 1.8，单个转场约 0.35–0.4 秒）；音效只用 PACK/音效库 的真实音效，不用代码合成；相邻转场换不同的声音；硬切不配音效；结尾只留一个重击。
3. 音效压在人声下面，整体 -14 LUFS。交付前用 ebur128 实测。
4. 成片默认**不带 BGM**，学员发布时自己加；想要 BGM 就在 `bgm` 里写文件。
5. 导出 1080×1920、H.264、约 4 Mbps、AAC 192k 48 kHz 立体声。
6. 每次改版另存新文件名（v1、v2…），渲染脚本和 project.json 留在项目文件夹里，不要只留在临时目录。

## 质检（逐项做完再说「好了」）
1. 抽帧拼联系表：开头、每个转场、结尾，逐张看；标题、数字卡、关键词、进度条没有遮住角色。
2. 查响度：`ffmpeg -i 成片.mp4 -af ebur128 -f null -`。
3. 逐句核对字幕和配音：对得上、不超前、无错字；双语时英文和中文意思一致。
4. 抽查转场处：转场和音效对得上，没有重复的声音。

## 合规
健身、健康类内容不写治病功效、不保证效果、不鼓励极端减重；训练动作提醒量力而行。学员确认「文案不改」就保留原文，只在交付时简短提示一次风险句，决定权在学员。

## 交付与收尾
